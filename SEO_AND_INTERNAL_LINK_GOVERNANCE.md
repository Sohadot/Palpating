# SEO and Internal Link Governance — Palpating

**Version:** 0.1 · **Status:** Binding · Subordinate to `ASSET_THESIS.md`.
Instantiates Non-Negotiable #4 (No random SEO) and the Agent Legibility
Requirement (`docs/INTELLIGENCE_FACTORY_DOCTRINE.md`).

Search visibility is **earned through reference quality**, never manufactured.
Palpating's SEO is **ontology-driven, not keyword-driven**: every page has a
knowledge reason to exist before it has a search reason.

---

## 1. The ordering rule

A page is created because the **Physical Sign Map requires the node**, then it is
made discoverable for the search intent that naturally intersects it. Never the
reverse. A keyword with no ontology node behind it does not become a page.

Forbidden (Non-Negotiable #4): keyword-stuffed pages, auto-generated thin pages,
doorway/comparison surfaces built for ranking, sitemap entries for incomplete
pages, and volume-without-precision. Any of these degrades the imitation barrier
and the asset's authority.

---

## 2. Clusters are ontology structure

Topic clusters are the ontology, made navigable:

    Physical Signs  ↔  Mechanical / Structural / Surface properties
          ↕
    Sensing Modalities  ↔  Digital Representation
          ↕
    Evidence  ↔  Applications / Limitations

A cluster is deep because the *knowledge* is deep, not because pages were spun
for coverage.

## 3. Internal links are relationship edges

Every internal link encodes a governed relationship from the Physical Sign Map
(property ↔ modality, property ↔ concept, claim ↔ evidence). Links are never
"you may also like." Consequences (binding):

- **No orphans, no dead ends.** Every page is reachable and links onward through
  real edges.
- The link graph is **useful to humans and agents simultaneously** — the same
  edges that guide a reader guide a machine reader.

## 4. Agent legibility (this is distribution)

Every page ships with:
- a **stable canonical URL** that does not change without a logged redirect;
- **stable identifiers** — terms `T-nn`, sources `S-nnn`, ontology class IDs;
- **structured metadata** (JSON-LD appropriate to the page type) and a concise
  **machine-readable summary**;
- explicit typing of statements as sourced fact / interpretation / framework
  language (so an agent can weight provenance correctly).

When category questions are answered by agents, the governed, consistent,
provenance-marked source wins. Agent legibility is not a nicety; it is how the
asset is distributed.

## 5. Metadata & distribution infrastructure

- One canonical URL per concept; hyphenated lowercase slugs; no tracking params
  in canonical links.
- `sitemap.xml` contains only complete, admitted pages (Non-Negotiable #1/#6).
- Social preview assets (Open Graph / Twitter cards) are part of distribution and
  are governed by `DESIGN_SYSTEM_GOVERNANCE.md` — designed artifacts, not
  screenshots.
- No aggressive tracking widgets, consent-banner-triggering third parties, or ad
  networks — they are incompatible with reference-authority positioning and with
  the static-first posture (Non-Negotiable #9; Execution Order Step 9).

> **Every page earns its place in the knowledge graph first, and the search graph
> second.**
